# Stick 2 Hero

A browser platformer where you collect the features of video games themselves. The game evolves from a 1978-style stick-figure prototype to a modern game. **PRD.md is the source of truth** for the design, the unlock ladder (section 6) and the milestones (section 14).

## Commands

- `npm run dev`: dev server (http://localhost:5173). Press backquote (`) to open the debug overlay: toggle features, change resolution, reset the save.
- `npm run check`: type-check + lint + tests. Run before calling anything done.
- `npm run build`: production build to `dist/` (static, relative paths). Add `?debug` to the URL to get the overlay in production.
- `?skipintro` in the URL goes straight past the tape loader. In dev, `window.__stick2hero` exposes `{ game, features, setScene, gameScene, ending }` for the console and browser automation (`ending()` jumps straight to the ending). Beating the Deprecator saves `cleared`, after which the finale starts out done: use "reset save" to fight it again.

## Architecture rules

- **Options aren't features.** The pause menu (`src/scenes/pause.ts`, Esc / Start, available from the start) holds controls/rebinding, volume and NEW GAME. Settings (`src/core/settings.ts`) and the high-score table (`src/core/scores.ts`) are stored apart from the save, so NEW GAME keeps them. Rebindable actions are `BINDABLE_ACTIONS` in `input.ts`; menus read the fixed `confirm`/`back`/`menu*` actions (Esc, Enter, arrows), which can't be rebound. Secrets are features with `secret: true` (the finale leaves them be).
- **Every feature gate goes through `FeatureRegistry`** (`src/core/features.ts`). Systems ask `features.has('X')`. Never add ad-hoc booleans for unlockable behaviour. New features get added to `FEATURE_IDS` + `FEATURES`.
- **Features gate abilities, never input devices.** Input always reads every key and gamepad. Game logic decides what's allowed.
- **Game logic (`src/game`, `src/world`, `src/core` apart from audio/input) is free of Pixi and the DOM** and covered by Vitest. Rendering only _reads_ game state.
- **Fixed 60Hz simulation** (`FixedLoop`). The render rate is separate and can be capped (15fps before `FRAME_RATE`). Renderers interpolate with `alpha`.
- **World units vs pixels:** one screen is always 320×180 world units (16×9 tiles of 20). The era's internal resolution (160×90, 320×180, …) only decides how many pixels draw it. Renderers convert using `s = width / VIEW_W`.
- **Tiered drawing:** each visual era has a renderer in `src/render/tiers/`. The low-res eras draw pixel-perfect into `PixelCanvas` (a 2D canvas uploaded as a texture). It goes `world → RenderTexture → nearest-neighbour upscaled sprite`. HD (Era 5) draws anti-aliased vector paths onto the same canvas (`p.context`) at `'native'` resolution, scaled smoothly (`Scene.smooth()`). BLOOM / POST-FX is one GPU filter on the final sprite (`src/render/postFx.ts`, chosen per frame by `Scene.postFx()`).
- **Stick man pose** comes from `src/render/stickman.ts` (a skeleton in world units, with the feet at the origin). Every tier draws the same skeleton in its own style.
- **Scenes** (`src/scenes/`): the tape loader, gameplay, the end-of-era screen and the ending. Each one picks its own resolution (checked every frame), render cap, and optionally smoothing, post-FX and a soundtrack override. `main.ts` switches between them.
- **Levels** are ASCII grids (`src/world/levels/`, one per era, listed in `index.ts`): `#` solid, `.` empty, `^` spikes, `~` hot bricks, `D` door, `P` spawn, `e` walker, `k` knight, `F` flag, `s` switch, `B` The Block, `V` Flicker, `W` The Warden, `w` water, `h` hollow wall, `g` ghost, `t` torch, `b` brazier, `C`/`X`/`Z` the Chase's start, finish and the Deprecator's spot, `%` cracked wall (PHYSICS), `l`/`L` street and hanging lamps, `<`/`>`/`*` drones looking left, right, or turning, `u` vent (updraft), `R` the Deprecator's arena (the finale), NPC letters defined in the level's `npcs` (with their dialogue), plus per-level pickup characters mapped to feature ids (see `tilemap.ts`). Levels are authored as 16×9 screens and assembled with `composeScreens`.
- **Level design rules** come from the player physics: 1–2 tile rises are jumpable, 3-tile rises need ARMS (ledge grab), 4+ need HANDS & FEET (wall jumps). A running jump clears about 58 units, so a 2-tile gap leaves little slack (spikes and hot bricks have inset hitboxes to help). Pickups must sit on solid ground, because collecting one sets the checkpoint there. Watch out for full jumps onto 1-tile steps overshooting into hazards. With the CAPE, holding jump glides about 6–7 tiles from a running jump (a 6-tile gap needs it); players hold jump a lot after that, so don't put a pickup just past a drop where a glide sails over it (the Era 5 bot found two).
- **Each era has a bot test** that plays its level (`tests/game.test.ts` for Era 0, then `tests/era1.test.ts` … `tests/era5.test.ts`; Era 5's also has a bot that beats the finale). The bots are crude players: when one dies a lot, check whether a human would too (they found a knight wandering into the Chase, and a pit with no run-up). If you change a level and its bot fails, it's usually telling you about a real fairness problem, not a bot bug.
- **Rendering per era:** `src/render/tiers/pixelTier.ts` draws Eras 0–3 with a palette per stage (mono white, phosphor green, COLOUR (4), COLOUR (16), then the PARALLAX "rich" style). Era 3's extras (parallax, knights, The Warden, NPCs, dialogue, face/outfit/sword) live in `era3Draw.ts`, and Era 4's (night sky, DEPTH, water, ghosts, lights, particles, LIGHTING, the cutscene and the Chase) in `era4Draw.ts`. The camera's zoom and shake are applied in `drawPixelTier`'s world-to-screen transform. Hot bricks are deliberately identical to normal bricks until there's colour.
- **Era 5** renders with `hdTier.ts` (frame, sky, skyline, rooftops, lighting with shadows, rain, the ENHANCE moment), `era5Draw.ts` (lamps, vents, drones and vision cones, robots, debris, the caped hero, the Deprecator) and `hdUi.ts` (HUD, banners, achievements, toasts, dialogue, photo mode and its filters); shared bits are in `hdCommon.ts`. **Below HD, Era 5's look follows its features** (`era5Style` in `pixelTier.ts`, `GameScene.resolution()`), so the finale rolls the game back through every palette and resolution to Era 0; `era5Pixel.ts` draws Era 5's things in whatever palette is current.
- **Shadows are shared geometry:** `src/world/light.ts` (line of sight, occluder edges, visibility polygons) decides both whether the player is lit (drones only see you in the light) and the drawn shadows and vision cones, so what you see is what the drones see.
- **The finale** (`src/game/finale.ts`) strips features in phases with `features.lock`; reclaimed features are banked and all come back when it's beaten. It keeps the list of what it took: `main.ts` saves those as collected, and leaving the fight (Game Over, era jump, reload) restores them.
- **Sounds** carry a world x (`hooks.sound(name, x)`); with SAMPLES + STEREO, `main.ts` pans them and adds a room. Off-screen knights' footsteps are the gameplay use. Soundtracks: `music.ts` (MUSIC's chiptune) and `cdMusic.ts` (CD AUDIO, with ADAPTIVE MUSIC's three extra layers faded in by `game.musicIntensity`), chosen every step by `syncMusic()` in `main.ts`; VOICE is formant synthesis in `audio.ts`. RUMBLE goes through `hooks.rumble` (gamepad haptics); without a gamepad the game pops the word itself up instead.
- Audio is procedural Web Audio (`src/core/audio.ts`) and only starts after a user gesture.
